# Local music acquisition

Переносимый локальный модуль для ограниченной загрузки пользовательского TXT-плейлиста.
Он не входит в серверный runtime AutPlay и не меняет продуктовую границу провайдеров.

Для постоянной работы на Linux-сервере используйте [серверную очередь](SERVER_QUEUE.md):
сохранение после каждого трека, восстановление после перезапуска, SHA-256, проверка аудио,
пауза, ограниченные повторы и отдельный счётчик ненайденных треков. Импорт в AutPlay остаётся
отдельным действием. Старый режим без `--queue-dir` сохраняет прежнее поведение.

For selective SOCKS5 downloads, see [on-demand Xray configuration](SERVER_QUEUE.md#on-demand-xray-for-acquisition).
Xray starts only when a selected provider begins acquisition and stops after the last
active download's idle timeout or when the acquisition runtime exits.

Порядок контуров фиксирован:

1. **Jamendo** — официальный API и повторная проверка `audiodownload_allowed`.
2. **Hitmo** — первые 20 результатов, проверка исполнителей и версии, локальный Edge по CDP.
3. **yt-dlp** — `ytsearch20`, проверка исполнителей и версии, только встроенный YouTube extractor.
4. **SoundCloud** — опциональный `scsearch20`, повторная проверка метаданных и загрузка полного
   незашифрованного аудио. Оригинал имеет приоритет; затем прямой MP3 без перекодирования.
5. **Bandcamp** — опциональный публичный поиск треков и бесплатные оригиналы, которые открыл
   автор: сначала MP3 320, затем MP3 V0 / FLAC и другие доступные форматы.
6. **Yandex Music** — опциональный контур на закреплённом commit
   `llistochek/yandex-music-downloader`, точное совпадение и OAuth-токен только из файла.

В коротких результатах YouTube учитывается поле `ie_key`. Для публикаций с одним названием
песни в заголовке загрузчик может проверить полные метаданные максимум трёх кандидатов
с подходящего подтверждённого канала. Перед скачиванием обязательны совпадающие теги
исполнителя и песни; одной отметки подтверждения канала недостаточно.

По умолчанию сохранён строгий режим: следующий контур открывается после подтверждённого
пропуска, а терминальная ошибка останавливает цепочку строки. DRM, наличие только превью или
отсутствие доступного оригинала — пропуски конкретной записи; они не отключают весь источник.
Ошибки сети и ограничения доступа остаются ошибками. Для пакетного
восстановления `--continue-on-provider-failure` разрешает переход после терминальной ошибки;
`--provider-failure-threshold 2` размыкает дважды подряд сломавшийся контур. Jamendo делает не
более одного повтора транспортного сбоя в ограниченном временном окне. `--workers 1..4`
обрабатывает разные строки параллельно, но каждый провайдер остаётся последовательной полосой:
два контура никогда не соревнуются за один трек.

Модуль предназначен только для материалов, на загрузку которых у пользователя есть права. Он не
обходит CAPTCHA и не использует cookies, логины, netrc, произвольные URL, динамические плагины
yt-dlp либо удалённые JS-компоненты. Yandex-контур работает только с явным OAuth-токеном аккаунта
и доступностью трека, которую сообщает API; ответственность за соблюдение условий сервиса остаётся
у пользователя.

## Установка

Нужны Python 3.12–3.14, `uv 0.12.3`, ffmpeg/ffprobe и Node.js. Сначала перейдите
в каталог переносимого модуля — это также избегает ограничений Windows launcher в Unicode-путях:

```powershell
Push-Location .\tools\local_music_acquisition
uv sync --frozen
```

Зависимости изолированы в каталоге модуля. Версия `yt-dlp[default,pin]` и точный commit
`yandex-music-downloader` зафиксированы в `uv.lock`; самообновление во время работы не выполняется.

Для Hitmo запустите отдельный видимый профиль Edge:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  .\scripts\start_hitmo_cdp_edge.ps1
```

## Формат плейлиста

Каждый плейлист проходит встроенную нормализацию до поиска и удаления дублей: Unicode NFKC,
пробелы, типографские кавычки и тире, невидимые форматирующие символы. При сопоставлении
учитываются перенос `feat.` / `w/` между названием и исполнителями, порядок совместных исполнителей
и авторов ремикса, разделители `-` / `|` в видеозаголовке и точные служебные подписи
`Official Audio` / `Official Music Video`. Названия версий
`live`, `remix`, `cover`, `slowed` и подобные сохраняются. Обрезанные слова не угадываются.

Подтверждённые исправления распознавания и обрезанных названий хранятся в переносимом
`normalization-catalog.json` внутри папки музыки и автоматически используются следующими
CLI-запусками. Можно указать другой каталог флагом `--normalization-catalog PATH`.
Каталог содержит `schema_version: 1` и массив `corrections`; каждая запись имеет
`source_artist`, `source_title`, `artist`, `title`, `evidence` (источник сверки) и, при наличии,
`duration_seconds`. Противоречивые исправления отклоняются. Исходный TXT остаётся неизменным;
очередь сохраняет преобразования и исходные строки в `normalization.json`.

Разделители исполнителей `vs.`, `vs` и `versus` между пробелами превращаются в запятые.
Все участники сохраняются; слова внутри названия песни не меняются. Правила применяются
к любому плейлисту, а исправления конкретных записей остаются во внешнем каталоге данных.

## Проверенные ссылки

`--source-catalog PATH` подключает локальный JSON-каталог ссылок. По умолчанию используется
`source-catalog.json` в папке результатов, если он существует. Пример для любого плейлиста:

```json
{
  "schema_version": 1,
  "entries": [
    {
      "artist": "Artist, Guest",
      "title": "Song (Live)",
      "kind": "download",
      "provider": "soundcloud",
      "url": "https://soundcloud.com/artist/song-live",
      "duration_seconds": 180,
      "evidence": "Reviewed artist publication"
    },
    {
      "artist": "Another Artist",
      "title": "Another Song",
      "kind": "reference",
      "url": "https://store.example/album/release",
      "evidence": "Purchase page; no automatic download"
    }
  ]
}
```

Для скачивания поддержаны страницы отдельных записей YouTube (`provider: yt_dlp`),
SoundCloud и Bandcamp. Ссылка заменяет поиск внутри соответствующего источника; порядок
источников остаётся прежним. Если ссылки для записи нет, работает обычный поиск. Источник
должен быть включён, а права подтверждены его обычным флагом. Каталог не включает источники
самостоятельно. При несовпадении версии/исполнителей ссылка получает пропуск и очередь
переходит к следующему источнику согласно общей политике.

Перед скачиванием повторно проверяются метаданные реальной страницы, идентификатор и источник.
Дальше действуют обычные проверки размера, длительности, DRM/превью и аудио. В режиме очереди
полное декодирование и SHA-256 обязательны. Из каталога нельзя скачать произвольный MP3,
локальный файл, плейлист или URL с паролем/токеном; встроенные экстракторы ограничены источником.
`kind: reference` сохраняет справочную или покупную страницу и никогда не отправляется на
скачивание. Покупки и авторизация в магазине этим механизмом не выполняются.

Каталог ограничен 2 MiB / 10 000 записями. Допускается одна ссылка на запись для каждого
источника. Конфликтующие ссылки, разные записи с одним адресом и некорректные данные
отклоняются до сети. Длительность необязательна; при конфликте с каталогом нормализации
загрузка останавливается для этого источника. Квитанция сохраняет SHA-256 каталога в
`identity_version`, без вывода адресов в обычный отчёт. `--check-runtime` проверяет каталог
и показывает только количество загрузочных и справочных записей.

Изменение ссылок не сбрасывает готовые файлы или бюджет очереди. Для `not_found` после
исправления ссылки используйте `queue retry --include-not-found`. Исправление идентичности
плейлиста требует нового каталога очереди, как и любое изменение нормализованного входа.

Проверка очереди включает полное декодирование ffmpeg, SHA-256 и длительность ffprobe.
Фрагменты короче 10 секунд не публикуются автоматически; при известной длительности источника
допустимое отличие — максимум из 3 секунд и 2%. Длительность из каталога имеет приоритет.
Короткие самостоятельные композиции требуют отдельной проверки.

Поддерживаются UTF-8 и CP1251, не более 500 валидных треков за запуск:

```text
Artist One<TAB>Track One<TAB>Optional Album
Artist Two - Track Two
```

`--normalize-numbered` удаляет префиксы `N.`/`N)` и строки `=== section ===`. Ошибочная строка
изолируется без обращения к провайдерам.

## Запуск контуров

Yandex выключен, пока не указан файл токена. На Linux создайте его вне репозитория с правами
`0600`; не передавайте токен в командной строке, логах или чате.

```powershell
uv run --frozen local-music-acquire `
  "D:\Playlists\tracks.txt" `
  --output-dir "D:\Music" `
  --jamendo-client-id-file "D:\Secrets\jamendo-client-id.txt" `
  --hitmo-rights-confirmed `
  --yt-dlp-rights-confirmed `
  --enable-soundcloud --soundcloud-rights-confirmed `
  --enable-bandcamp --bandcamp-rights-confirmed `
  --yandex-token-file "D:\Secrets\yandex-oauth-token.txt" `
  --yandex-rights-confirmed `
  --continue-on-provider-failure `
  --provider-failure-threshold 2 `
  --workers 4 `
  --normalize-numbered
```

После работы вернитесь в корень репозитория командой `Pop-Location`.

Флаги подтверждают права на каждый трек очереди до первого сетевого запроса. Первые три контура
можно убрать флагами `--disable-jamendo`, `--disable-hitmo` и `--disable-yt-dlp`; Yandex включается
только присутствием `--yandex-token-file`.

SoundCloud и Bandcamp включаются отдельно через `--enable-soundcloud` / `--enable-bandcamp`.
Для них нужны соответствующие `--soundcloud-rights-confirmed` / `--bandcamp-rights-confirmed`.
Существующие команды без этих флагов сохраняют прежний набор источников. Тайм-аут каждого
нового источника по умолчанию 120 секунд; настройка — `--soundcloud-timeout` / `--bandcamp-timeout`
в диапазоне 10–600 секунд. Повторы принадлежат общей очереди, а не скрытому циклу провайдера.

Оба новых контура проверяют первые 20 результатов и полные метаданные максимум трёх точных
кандидатов. Проверяются все исполнители, версия, идентификатор и адрес записи. У SoundCloud
теги издателя имеют приоритет; совпадения одного имени загрузившего пользователя недостаточно.
Превью SoundCloud исключаются до передачи файла. У Bandcamp поток `mp3-128` для прослушивания
не считается оригинальной загрузкой. Платные релизы, выдача через email и файлы из покупок,
требующие входа, автоматически не приобретаются: результат `original_download_unavailable`.
Вход в аккаунт и ссылки из заказов этим контуром не поддерживаются.

Если с сервера недоступна главная страница SoundCloud, но работает его API, можно заранее
получить публичный идентификатор веб-клиента из доступной сети:

```sh
local-music-acquire soundcloud-client-id --output ./soundcloud-client-id
```

Перенесите файл на сервер с правами `0600` и задайте `--soundcloud-client-id-file PATH`.
Это публичная служебная настройка SoundCloud, а не токен аккаунта. Она применяется к любому
треку и поиску SoundCloud. Пакет помещает её в собственный временный кеш закреплённого yt-dlp;
проверки записей и аудио сохраняются. Без файла действует стандартное получение идентификатора.
Если сервис сменит идентификатор, повторите команду из сети, где открывается главная страница,
и обновите серверный файл. Команда не выводит идентификатор в журнал и ограничена 60 секундами.

Перед публикацией проверяются размер, тип аудио, длительность и полное декодирование ffmpeg.
Формат исходного файла сохраняется. Новые контуры работают без cookies, Node.js,
внешних плагинов и браузера. Разрешены только встроенные экстракторы своего
источника; подписанные адреса файлов не попадают в отчёт.

Пример повторного прогона пропусков только через новые источники:

```powershell
uv run --frozen local-music-acquire "D:\Music\remaining.txt" `
  --output-dir "D:\Music" --queue-dir "D:\Music\queues\extra-sources" `
  --disable-jamendo --disable-hitmo --disable-yt-dlp `
  --enable-soundcloud --soundcloud-rights-confirmed `
  --enable-bandcamp --bandcamp-rights-confirmed --workers 2
```

JSON-результат содержит номера строк, статусы, имена провайдеров и единообразные сокращённые
SHA-256 отпечатки загруженных байтов, но не абсолютные пути и не названия треков. Сокращённый
отпечаток нужен только для privacy-redacted correlation и не является доказательством целостности
или ключом дедупликации. Код `0` означает полную загрузку, `1` — завершённый прогон с
пропусками/ошибками, `2` — ошибку входных данных или конфигурации.

## Отдельный Hitmo-контур

Старая команда сохранена как совместимый launcher:

```powershell
uv run python .\final_script.py `
  --artist "Рубеж веков" --title "О боли" `
  --browser cdp --download-dir "D:\Music" `
  --download --rights-confirmed
```

Hitmo сохраняет privacy-redacted evidence во внешнем writable-каталоге
`$AUTPLAY_HITMO_EVIDENCE_ROOT/run_<n>` (по умолчанию — системный temp); скриншоты создаются только
с `--evidence-screenshots`. Это позволяет запускать пакет в read-only контейнере.

## Перенос

Скопируйте целиком `tools/local_music_acquisition` в другой каталог. Для работы не нужны
`server/src`, Android-проект или корневой Python-пакет AutPlay:

```powershell
Set-Location D:\Portable\local_music_acquisition
uv sync --frozen
uv run local-music-acquire --help
uv run python -m pytest -q
```

Корневые `scripts/jamendo_download.py` и `scripts/txt_track_import.py` — только совместимые
обёртки; канонические реализации находятся в `src/local_music_acquisition`.
