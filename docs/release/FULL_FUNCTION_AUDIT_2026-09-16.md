## Дефекты

### F01 — P1. Выбор English вызывает падение и блокирует последующие запуски

- **Подтверждение:** M52 → Настройки → Оформление → English. Приложение закрывается; повторный запуск падает с той же ошибкой. `IllegalStateException: No ActivityResultRegistryOwner was provided via LocalActivityResultRegistryOwner`.
- **Причина:** `MainActivity.kt:591–636`, `AppLanguageProvider` подставляет в `LocalContext` результат `createConfigurationContext`; `OfflineLibraryScreen` регистрирует launcher в `MainActivity.kt:699`. Новый контекст не предоставляет владельца Activity Result. Контракт поиска владельца описан в [AndroidX](https://developer.android.com/reference/kotlin/androidx/activity/compose/LocalActivityResultRegistryOwner).
- **Восстановление:** сохранена копия состояния сбоя, изменён только ключ языка обратно на исходный SYSTEM и очищено установленное аудитом framework locale. Приложение снова запускается; остальные настройки совпали с исходными. [Журнал двух падений](evidence/full-audit-2026-09-16/LANGUAGE_CRASH.txt).
- **Исправление:** сохранить ActivityResultRegistryOwner до замены контекста и передать явно; альтернативы — Activity-связанный ContextWrapper или переход на поддерживаемые per-app locale API. Для быстрого восстановления выбран возврат единственного изменённого ключа; production-код в этом аудите не исправлялся. Нужен тест полной MainActivity для SYSTEM → EN → RU → SYSTEM и холодного запуска на API 26/33. [Рекомендации Android по языкам](https://developer.android.com/guide/topics/resources/app-languages).
- Сбой Русского языка отдельно не воспроизводился; общий путь кода делает его кандидатом на тот же дефект.

### F02 — P2. Локальный поиск не находит синхронизированную библиотеку

- **Подтверждение:** на M52 трек `THE LAST OF US Ambient` виден в библиотеке, запросы `THE` и `LAST` возвращают 0 результатов.
- **Доказательство:** в исходной копии базы 57 `user_track_ref`, 56 `library_entry`, **0 `track_search_content`**; две записи известного названия, ни одна не индексирована. [Числа](evidence/full-audit-2026-09-16/SEARCH_PROJECTION.json).
- **Причина:** `LocalTrackSearchRepository.kt:19` ищет через FTS; `SyncEngine.kt:574–589` обновляет метаданные, но не поисковую проекцию. Заполнение проекции имеется у локального добавления, а у синхронизации отсутствует.
- **Исправление:** единый транзакционный upsert поисковой проекции для локальных и удалённых изменений плюс восстановление проекции уже существующих записей. Рассмотрены: обновление проекции при sync, триггеры из канонической таблицы, восстановление индекса, временный LIKE-поиск. Предпочтителен первый вариант с backfill; один `rebuild` не поможет, пока сама content-таблица пуста. Это соответствует устройству [SQLite FTS5 external content](https://www.sqlite.org/fts5.html#external_content_tables). Нужны проверки создания, переименования, удаления и изоляции профилей.

### F03 — P2. Нельзя снять лайк в библиотеке и карточке трека

- **Подтверждение:** M52, карточка уже понравившегося трека: кнопка «Понравилось» отключена. Аналогичный запрет в строке библиотеки.
- **Код:** `ui/CoreProductDetailScreen.kt:140`, `ui/CoreProductScreens.kt:1144`: `enabled = !track.loved`. Обработчик переключения LIKED → NEUTRAL уже существует в `CoreCommandActions.kt:322–326`, но нажатие до него не доходит.
- **Исправление:** доступность должна зависеть от возможности выполнить действие и незавершённого запроса, а не от текущего лайка. Проверить два последовательных нажатия и сохранение после перезапуска. Лайк пользователя во время аудита не менялся.

### F04 — P2. Полный плеер отключает правильные переходы при Repeat All и Shuffle

- **Подтверждение:** разбор связки UI → очередь. `ui/player/PlaybackPlayerSurfaces.kt:373,385` использует `queueState.canPrevious/canNext`; `application/playback/QueueEditorRepository.kt:156–157` вычисляет их по линейному индексу.
- **Последствие:** на конце списка Next заблокирован даже при Repeat All; на линейной границе также может блокироваться допустимый сосед в перемешанной очереди.
- **Исправление:** брать доступность перехода из фактического состояния Media3, согласованно с соседними mediaId. Нужны UI-проверки начала/конца очереди при repeat/shuffle. На реальной музыке M52 эти режимы в данном аудите не воспроизводились.

### F05 — P2. Отзыв о рекомендации снимает исключение из профиля вкуса

- **Подтверждение:** `CoreCommandActions.kt:117–123`, `recordHomeFeedback` передаёт `excludedFromTaste = false` в сохраняющий обработчик предпочтения.
- **Последствие:** Like/Dislike рекомендации перезаписывает ранее выбранное исключение трека из вкусового профиля. В другой ветке `LibraryVerticalSliceRepository.kt:116–131` это свойство сохраняется.
- **Исправление:** менять только оценку и её атрибуцию, сохранять исключение. Нужен тест «исключённый трек → Like/Dislike → сохранение/синхронизация». Подтверждено кодом; пользовательские предпочтения не изменялись для воспроизведения.

### F06 — P2. Ошибки изменения очереди и управления загрузкой не видны на нужном экране

- **Подтверждение:** `MainActivity.kt:1252,1523,1538` записывает `stableError`; видимый вывод находится в `LegacySecondaryRouteRenderer.kt:204`. Основные маршруты плеера/загрузок обходят этот renderer (`MainAdaptiveShell.kt:159`).
- **Последствие:** неудачный cancel/retry или изменение очереди может выглядеть как неработающая кнопка. Старое сообщение может появиться позже на другом маршруте.
- **Исправление:** общий видимый snackbar либо состояние ошибки конкретного экрана с очисткой/повтором. Нужна проверка отказа repository на каждом маршруте. Это подтверждение связки кода, без искусственного сетевого отказа на M52.

### F07 — P2. Карточка обещает доступный звук без проверки источника

- **Подтверждение:** `application/library/CoreProductRepository.kt:184–188` считает серверное воспроизведение доступным по идентификаторам, RESOLVED и отсутствию удаления. Карточка пишет «Можно воспроизвести с вашего сервера», хотя наличие аудиоварианта не установлено.
- **Реальный resolver:** серверный lookup подключён. `ServerFeatureRepository.kt:249–262` превращает HTTP 404 в отсутствие варианта; другие ошибки становятся ошибкой авторизации/доступа. Backend дополнительно требует действующий canonical variant и подтверждённую доступную реплику (`vault_runtime.py:540–594`).
- **На M52:** текущий трек не имеет локальной аудиокопии, плеер выдаёт `NO_AUDIO_SOURCE`; профиль также показывает недоступность сервера. Точная серверная причина отсутствия звука не доказана. Это не доказательство поломки декодера или пропущенного запроса.
- **Исправление:** различать возможный серверный источник и подтверждённую доступность; разрешать попытку, но не обещать воспроизведение заранее.

### F08 — P3. Отсутствующий альбом отображается как `null`

- **Подтверждение:** M52, карточка `THE LAST OF US Ambient`.
- **Причина:** `SyncEngine.kt:551–553` использует `jsonPrimitive.content`; JSON null становится строкой `"null"`, затем сохраняется в `rawAlbum` (`:587`) и показывается в карточке (`CoreProductDetailScreen.kt:125`). Поведение и `contentOrNull` описаны в [kotlinx.serialization](https://kotlinlang.org/api/kotlinx.serialization/kotlinx-serialization-json/kotlinx.serialization.json/-json-null/).
- **Исправление:** различать отсутствующий ключ и явный null; восстановить уже сохранённые неправильные значения. Простая замена на `contentOrNull` вместе с существующим `?: row.rawAlbum` оставит старую строку. Аналогичный helper используется для названия, исполнителя и описания плейлиста.

## Незавершённые функции и оставшиеся проверки

- На главной «Подборки под момент» отключены намеренно (`CoreProductScreens.kt:265`), строки новых релизов не имеют действия (`:281`). Это заготовки интерфейса, а не проверенные рабочие функции.
- `LocalServerProvisioningTest` без специального флага фактически не выполняет provisioning. Отдельный сценарий подключения/отзыва M5B выполнен, но он не заменяет первичное развёртывание реального сервера.
- Нужны живые проверки сервера M52: реальный stream, download, переключение Wi‑Fi/мобильной сети и офлайн, долговременное фоновое воспроизведение, Bluetooth/гарнитура/автомобиль, системные медиакнопки, синхронность Wave на нескольких устройствах.
- Windows-проверку symlink нужно повторить на хосте с разрешённым созданием ссылок.
- Настоящую полноту исправления языка, индекса и ошибочных UI-связок следует подтверждать новыми интеграционными сценариями полной MainActivity.
