# Начало работы с AutPlay 1.0.8

AutPlay — Android-приложение для собственной музыки с необязательным личным сервером.
Для установки нужен Android 8.0 или новее. APK распространяется напрямую через
[GitHub Release](https://github.com/Dakstar-cool/AutPlay/releases/tag/v1.0.8).

## Установка и обновление

1. Скачайте `autplay-1.0.8-production.apk` и `SHA256SUMS` из выпуска.
2. Сравните SHA-256 файла с опубликованной суммой.
3. Откройте APK на телефоне и разрешите установку для используемого браузера или файлового
   менеджера. После установки разрешение можно выключить.
4. Запустите AutPlay и откройте «Моя музыка» → «Добавить локальный трек».
5. Выберите аудиофайл системным диалогом Android и включите воспроизведение.

```powershell
Get-FileHash .\autplay-1.0.8-production.apk -Algorithm SHA256
```

```bash
sha256sum autplay-1.0.8-production.apk
```

Пакет — `app.autplay`, версия — `1.0.8`, build — `21`. На физическом Samsung M52 проверено
обновление production-подписанной 1.0.6 до 1.0.8 без удаления приложения или очистки данных.
Сохранились привязка, проверенные строки библиотеки, статистика и позиция воспроизведения.

APK с другой подписью Android не установит поверх существующего приложения. Старый комплект
0.4.0 использовал development-ключ. Если в нём есть важные локальные данные, сначала сохраните
их: удаление приложения стирает его локальную базу, настройки и загрузки. AutPlay LAN — отдельный
пакет; его данные автоматически не объединяются с `app.autplay`.

## Локальный аккаунт

В профиле откройте раздел «Аккаунт», выберите ID и задайте пароль или фразу из 15–128 символов.
Создание аккаунта не требует подключения к серверу. Сохраните файл восстановления либо код
в надёжном месте отдельно от телефона.

Аккаунт и локальная музыка доступны без сети. Для использования аккаунта на новом телефоне
нужна его ранее сохранённая копия на совместимом сервере либо файл восстановления.
Пароль сам по себе не восстанавливает данные, которые никогда не покидали потерянный телефон.

## Подключение сервера и другого телефона

1. Выберите сервер через экран подключения и подтвердите его идентичность.
2. В разделе «Аккаунт» сохраните на нём свой аккаунт либо войдите в существующий по ID и паролю.
3. Для добавления другого телефона используйте «Добавить телефон» и встроенный QR-сканер.
4. Откройте статистику в профиле; обновите данные после синхронизации.

Сервер должен объявлять возможности `portable_accounts` и, для QR-привязки другого телефона,
`self_device_pairing`. Они включаются оператором независимо и по умолчанию выключены.
[Конфигурация сервера](PORTABLE_ACCOUNTS.md) описывает требования.

Смена сервера сохраняет UUID аккаунта. Синхронизируются история, предпочтения, плейлисты и
данные вкуса. Аудиофайлы и права доступа к чужому хранилищу вместе с аккаунтом не переносятся.
Статистика аккаунта объединяет синхронизированные прослушивания; без доступной серверной
статистики приложение может показывать локальную статистику с соответствующей подписью.

## Выход и восстановление

Отключение переносимого аккаунта и серверные операции выхода требуют ID и пароль.
Если пароль потерян, используйте «Забыл пароль / восстановить аккаунт» с сохранённым файлом
или кодом. Для восстановления только по коду нужен документ аккаунта на телефоне либо
доверенном сервере.

Восстановление сохраняет UUID и создаёт новый ключ. Серверный сброс отзывает прежний доступ
на выбранном сервере; другие независимые серверы обновляются при последующем подключении.
После сброса сохраните новый файл восстановления.

## Самостоятельное развёртывание

В [выпуске 1.0.8](../release/RELEASE_NOTES_1.0.8.md#server) доступен совместимый CPU-образ
сервера `linux/amd64`. Это архив Docker image, а не готовый установщик со всеми настройками.
Понадобятся PostgreSQL, Vault, постоянная идентичность сервера, секреты, HTTPS и резервное
копирование. Перед изменением действующей базы обязательны проверенная копия и процедура
миграции из [runbook развёртывания](DEPLOYMENT.md).

Не используйте старый установщик 0.4.0 для получения новых функций аккаунта. Его
[историческая инструкция](INSTALL_AND_PAIR.md) относится только к доверенной LAN-топологии.
