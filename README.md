## Ваша коллекция. В вашем ритме.

- **Библиотека, которую собираете вы.** Локальные треки, исполнители, альбомы и плейлисты;
  поиск, редактирование тегов и обложек.
- **Плеер под рукой.** Очередь, свайпы по обложке, лайки и управление из уведомления.
  Позиция и очередь сохраняются после перезапуска.
- **Музыка без сети.** Локальные файлы и заранее загруженные треки из вашего хранилища
  доступны, когда сервер отключён.
- **История ваших прослушиваний.** Локальная статистика на телефоне и общая статистика
  аккаунта после синхронизации устройств.
- **Оформление под себя.** Светлая или тёмная тема, четыре акцентных цвета, русский
  или английский интерфейс.
- **Комната для совместного прослушивания.** С личным сервером — общая очередь,
  приглашения и синхронное воспроизведение на нескольких устройствах.
  [Последние изменения комнат](#rooms).

<a id="start"></a>

## От установки до первого трека

1. [Скачайте APK](https://github.com/Dakstar-cool/AutPlay/releases/download/v1.0.8/autplay-1.0.8-production.apk)
   и установите AutPlay на телефон.
2. Откройте **«Моя музыка» → «Добавить локальный трек»** и выберите аудиофайл.
3. Нажмите воспроизведение. Для локальной музыки подключение к серверу не требуется.

[Инструкция по установке и обновлению](docs/operations/GET_STARTED_1.0.8.md) ·
[Что нового в 1.0.8 и SHA-256 APK](https://github.com/Dakstar-cool/AutPlay/releases/tag/v1.0.8)

Обновление подписанной версии **1.0.6 → 1.0.8** проверено с сохранением данных приложения.
Если Android сообщает о другой подписи, сначала сохраните важные локальные данные:
старые development-сборки использовали другой ключ.

<a id="account"></a>

## Один аккаунт — несколько устройств

Создайте аккаунт с ID и паролем прямо на телефоне и сохраните файл восстановления.
Позже подключите его к совместимому серверу: другой телефон можно добавить через QR
или войти на нём по ID и паролю.

<p align="center">
  <img src="assets/readme/account-flow.svg" width="100%" alt="Телефон хранит музыку и аккаунт локально. Личный сервер синхронизирует историю, предпочтения и плейлисты между устройствами того же аккаунта.">
</p>

История, предпочтения и плейлисты следуют за аккаунтом при смене совместимого сервера.
Для входа на новом телефоне нужна сохранённая серверная копия аккаунта либо файл
восстановления. Аудиофайлы передаются отдельно.

Выход и отключение аккаунта защищены проверкой ID и пароля. Если пароль потерян,
сохранённый файл или код восстановления поможет вернуть доступ.

[Подключение аккаунта, QR и восстановление](docs/operations/GET_STARTED_1.0.8.md#локальный-аккаунт)

<a id="rooms"></a>

## Слушайте вместе в комнате

Создайте комнату в разделе **«Совместное прослушивание»**, пригласите участников
и соберите общую очередь. Ведущий выбирает музыку, запускает её и ставит на паузу;
сервер согласует воспроизведение на **восьми устройствах**, включая ведущего.

<p align="center">
  <img src="assets/readme/room-flow.svg" width="100%" alt="Ведущий собирает общую очередь комнаты; личный сервер согласует старт, а участники слушают на своих устройствах. До восьми устройств, каждому нужен собственный доступ к музыке.">
</p>

**Что нового в комнатах:**

- **Музыка прямо из медиатеки.** Добавляйте треки в очередь комнаты; на экране видны
  название, исполнитель, текущий трек и доступность на вашем устройстве.
- **Подготовка перед стартом.** Комната проверяет доступность музыки и готовность устройств.
  Кнопка **«Подготовить следующий трек»** готовит следующий пункт очереди; после этого
  ведущий запускает его кнопкой **«Начать воспроизведение»**.
- **Приглашения для разных участников.** Укажите ID аккаунтов того же сервера и поделитесь
  кодом комнаты из десяти символов. Для гостя без аккаунта есть отдельное приглашение.
- **Возвращение после обрыва связи.** Клиент восстанавливает состояние комнаты и текущую
  позицию по данным сервера, без повторного запуска уже применённой команды.
- **Выход к своей музыке.** Участник может выйти, а ведущий — закрыть комнату для всех
  с подтверждением. Предыдущая личная очередь и позиция восстанавливаются, если вы
  за это время не включили другую очередь.

Чтобы начать, подключите аккаунт к совместимому серверу, создайте комнату и добавьте
синхронизированные с сервером треки из медиатеки. Приглашённый участник вводит код комнаты;
гость открывает отдельное гостевое приглашение. **Каждому устройству нужен собственный
доступ к треку** — локальный файл, готовая загрузка или разрешённый поток из Vault.
Приглашение само по себе не передаёт аудиофайлы и не открывает чужое хранилище.

## Личный сервер для вашей музыки

AutPlay работает самостоятельно на телефоне. Личный сервер расширяет его возможностями:

- **Vault** хранит вашу коллекцию и отдаёт музыку для потокового воспроизведения или загрузки.
- **Синхронизация** объединяет данные аккаунта и историю устройств.
- **Комнаты** согласуют общую очередь и воспроизведение на устройствах участников.
- **Web Admin** помогает управлять хранилищем, устройствами и задачами сервера.

Сервер работает на CPU. Для самостоятельного развёртывания нужны PostgreSQL, хранилище,
секреты, HTTPS и резервное копирование. Исходники и инструкция доступны в репозитории;
во вложениях релиза 1.0.8 размещён только Android APK.

[Развёртывание сервера](docs/operations/DEPLOYMENT.md) ·
[Настройка аккаунтов](docs/operations/PORTABLE_ACCOUNTS.md) ·

<a id="developers"></a>

## Для разработчиков

Android-приложение написано на **Kotlin и Jetpack Compose**; для библиотеки и воспроизведения
используются Room, Media3 и WorkManager. Сервер — **Python и PostgreSQL** с файловым
хранилищем аудио. API и форматы обмена находятся в `contracts`.

[Окружение и сборка](docs/operations/FULL_PROJECT_SETUP.md) ·
[Архитектура](docs/design/AutPlay%20System%20Architecture%20v1.md) ·
[Комнаты: код, API и проверки](docs/development/WAVE_ROOMS.md) ·
[Проверки и выпуск](docs/operations/CI_RELEASE.md) ·
[Сообщить об ошибке](https://github.com/Dakstar-cool/AutPlay/issues)

**При работе с комнатами:** PostgreSQL хранит очередь и команды; REST изменяет состояние
и возвращает снимки для восстановления, WebSocket уведомляет об изменениях, а Media3
воспроизводит музыку на каждом устройстве. Поле снимка `playback_command` связывает
восстановление с последней сохранённой командой. Меняйте клиент, сервер и
[OpenAPI](contracts/openapi/v1/autplay-wave.openapi.json) согласованно.

<summary>Команды подготовки и проверки проекта</summary>

Запускайте команды из корня репозитория. Текущие закреплённые версии:

для установки актуального APK используйте [инструкцию 1.0.8](docs/operations/GET_STARTED_1.0.8.md).

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1
```

```bash
bash scripts/bootstrap.sh
bash scripts/check.sh
```

Для серверного контура используйте `-ServerOnly` в PowerShell или `--server-only`
в Bash. Полная проверка поднимает собственную временную базу и очищает её после выполнения.
При изменениях комнат нужны проверки протокола, серверного runtime, очереди и восстановления,
а также Android unit- и instrumentation-тесты; [точные команды и сценарии](docs/development/WAVE_ROOMS.md#checks).

APK 1.0.8 собран из commit `2b0a843` с параметрами
`-Pautplay.versionName=1.0.8 -Pautplay.versionCode=21 -Pautplay.productionRelease=true`.
Тег `v1.0.8` содержит тот же код приложения. Для замены установленного подписанного APK
нужен тот же ключ выпуска.
